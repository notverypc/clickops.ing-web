I loved AppleScript. Building scripts and simple apps with it was easy, the code was easy to read, and it was good fun.

Before Google Reader came along, I used [Vienna](https://www.vienna-rss.com) as my RSS reader. I had a work eMac and a home iBook, so I wrote a small AppleScript app that kept Vienna in sync between them, using my iPod to carry the data back and forth. The script checked that the iPod was connected, then copied the Vienna database across. It was simple, but it saved me from losing track of what I'd already read.

AppleScript did have a catch, though. Once a script grew past simple, the thing that made it easy started to hold it back. The language that read like English was hard to push further.

Over the years I've written plenty of "hello world" scripts in Bash and Python. I've finished a lot of coding courses, and nearly finished a few more (thanks, ADHD). I never quite got back the feeling AppleScript gave me.

## Now there's AI

My process starts the same way it always has. I draw out what I want to build, then I refine it. Once I'm happy with it, I start a planning session with Claude.

Claude writes the code, and I read it and test it.

This blog is a good example. I started it as a project to help me understand vibe coding, and I've built it the same way. I describe what I want, such as simplifying the site down to Markdown posts that GitHub Pages builds, or moving the About section to its own page. Claude makes the changes, and I review each one before I merge it. Even this post started as an outline that I handed to Claude to shape into a draft.

To me, that feels like what AppleScript promised: coding in natural language.

So is AI the AppleScript I always wanted... I think it could be.
